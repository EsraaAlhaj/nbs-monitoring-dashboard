# NbS Impact Monitoring Dashboard (Prototype)

An interactive Streamlit dashboard prototype for visualising how paired
micro-climate monitoring stations could track the cooling impact of
**Nature-based Solutions (NbS)** — vegetated green infrastructure — compared
to nearby unplanted reference sites, using the University of Jordan campus
as the illustrative case.

> **This prototype uses 100% synthetic, simulated data.** No physical
> sensors, field stations, or live data feed exist yet. Every chart, table,
> and figure in this app is generated by [`src/data_generator.py`](src/data_generator.py)
> and stored in a local SQLite database for demonstration purposes only. See
> [Data disclaimer](#data-disclaimer) below.

## What this prototype demonstrates

Two station **pairs**, each consisting of a "green" (vegetated) site and a
nearby unplanted "reference" site, so the two members of a pair experience
the same regional weather and differ mainly in local land cover:

| Pair | NBS site | Reference site |
|---|---|---|
| Proposed Pair 1 — Student Housing Area | Pair 1 — Green Site — vegetated green-infrastructure (candidate location, not field-verified) | Pair 1 — Reference Site — nearby unplanted open ground (candidate location, not field-verified) |
| Proposed Pair 2 — Agriculture and Gardens Area | Pair 2 — Green Site — vegetated green-infrastructure (candidate location, not field-verified) | Pair 2 — Reference Site — nearby unplanted open ground (candidate location, not field-verified) |

For each of the 4 stations, the simulator produces 30 days of summer data
at 15-minute resolution: air temperature, relative humidity, wind speed &
direction, solar radiation, rainfall, an estimated Mean Radiant Temperature
(MRT), and an estimated Universal Thermal Climate Index (UTCI) computed with
the [`pythermalcomfort`](https://pythermalcomfort.readthedocs.io/) library.
The green sites are modelled to be measurably cooler than their paired
reference sites during daylight hours, with the cooling effect scaling with
solar radiation rather than being a fixed offset — reflecting how shade and
evapotranspiration actually behave.

The dashboard also simulates realistic operational imperfections —
maintenance/offline periods, missing readings, an implausible-value anomaly,
and a stuck-sensor anomaly — so the **Data Quality** page has something
real to detect and report.

## Data disclaimer

- **Station names are proposed candidate locations, not field-verified.**
  The four stations are currently labelled Pair 1 — Green/Reference Site and
  Pair 2 — Green/Reference Site (grouped under "Proposed Pair 1 — Student
  Housing Area" and "Proposed Pair 2 — Agriculture and Gardens Area"), with
  `latitude`/`longitude`/`elevation_m` left unset (`None`) — these names
  have not been field-verified or formally approved. Once real
  sites are confirmed, add their GPS coordinates to `STATIONS` in
  [`config/settings.py`](config/settings.py) (avoiding the Clock Tower
  plaza, per `EXCLUDED_LANDMARK`) — no other file needs to change. See
  `STATION_SITING_DISCLAIMER` in [`config/settings.py`](config/settings.py).
- **All readings are synthetically generated**, seeded for reproducibility
  (`RANDOM_SEED = 42`). No live field-station connection exists.
- **Mean Radiant Temperature and UTCI are simplified computed estimates**
  derived from the simulated weather variables — not field measurements
  from a globe thermometer or a validated radiation-budget model. This is
  repeated in-app via a persistent banner and an estimate note wherever MRT
  or UTCI values are shown.

```
  database.py             SQLite schema, inserts, and fetch queries.
  data_service.py         Backend-agnostic DataSource interface (SQLite today,
                         API-ready) — see "Extending to real field stations".
  cached_data.py          Streamlit @st.cache_data wrappers around data_service;
                         pages import from here.
  statistics_utils.py     Pair comparisons, cooling-hour stats, hottest
                         periods, hourly profiles, summary statistics.
  quality_checks.py       Completeness, time-gap, implausible-value, and
                         stuck-sensor detection; station status summaries.
  styling.py              Shared CSS injection, page header, demo banner,
                         estimate-disclaimer helper, Plotly layout template.
app.py                  Multipage entry point (Streamlit st.navigation router;
                         run this with `streamlit run app.py`).
views/
  overview.py             Station map, status table, per-pair cooling cards.
  network_trends.py       Multi-station/multi-pair trend explorer, one panel
                         per Monitoring Area, shared time axis and scale.
  site_comparison.py      Green vs. reference comparison for a selected pair.
  thermal_statistical_analysis.py  UTCI Analysis and Statistical Analysis,
                         combined as tabs on one page.
  data_quality_downloads.py  Data Quality and Downloads, combined as tabs
                         on one page.

  generate_data.py        CLI to (re)build the SQLite database from scratch.
database/
  monitoring.db            SQLite file (created by generate_data.py; not
                          committed — regenerate locally, see below).

requirements.txt
.streamlit/config.toml   Theme (calm green, no third-party branding).
```

## Setup

Requires **Python 3.11+** (developed and tested on Python 3.14).

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

> **Windows note:** on machines with an Application Control / WDAC policy
> that blocks DLLs loaded from a project-local virtual environment, you may
> see `ImportError: DLL load failed ... An Application Control policy has
> blocked this file` when importing pandas from `.venv`. If that happens,
> install the requirements into your system Python instead
> (`C:\PythonXY\python.exe -m pip install -r requirements.txt`) and invoke
> all commands below with that interpreter — this is a local machine policy
> issue, not a bug in the project.

## Running the app

1. **Generate the synthetic dataset** (creates/populates `database/monitoring.db`):

   ```powershell
   python scripts/generate_data.py --reset
   ```

   Re-run any time you want a fresh copy; `--reset` drops and recreates the
   schema first. Omit `--reset` to upsert into an existing database. Use
   `--seed <int>` to generate a different (still reproducible) draw.

2. **Launch the dashboard:**

   ```powershell
   streamlit run app.py
   ```

   Streamlit will open the Overview page in your browser (default
   `http://localhost:8501`) and list the other 4 pages in the sidebar.

## Pages

| Page | Purpose |
|---|---|
| **Overview** | Current-pilot summary, station map, current status table, per-pair "cooling effect right now" cards. |
| **Network Trends** | Multi-station / multi-pair explorer: pick any stations (or All Stations), a variable, date range, hour-of-day window, and display resolution (raw/hourly/daily); each Monitoring Area (site pair) is plotted in its own panel, sharing one time axis and value scale. |
| **Site Comparison** | Green vs. reference time series for a chosen pair/variable/date range, cooler-hours share, hottest-period table. |
| **Thermal & Statistical Analysis** | Two tabs: *UTCI Analysis* (UTCI over time, heat-stress category distribution and hours-per-category, full category table for green vs. reference) and *Statistical Analysis* (summary statistics, scatter vs. a second variable, boxplot, histogram — filterable by station, variable, date range, hour-of-day). |
| **Data Quality & Downloads** | Two tabs: *Data Quality* (completeness by station, station-status breakdown, time-gap list, implausible-reading list, stuck-sensor list) and *Downloads* (CSV export of filtered raw readings, and of pair-comparison / cooling-summary / hottest-periods tables). |

## Configuration

Everything site-specific or simulation-specific lives in
[`config/settings.py`](config/settings.py) — station coordinates and metadata,
the simulated period and interval, variable units/valid ranges, QC
thresholds (gap/stuck-sensor thresholds), the UTCI category table, and the
colour palette. No other module hard-codes these values, so updating this
one file (e.g. once real GPS coordinates are available) propagates
everywhere.

## Tests

```powershell
pytest tests/ -v
```

36 tests cover:
- `comfort.py` — MRT day/night/wind behaviour, wind-height log-law
  conversion, UTCI sanity bounds and Series support, category
  classification.
- `data_generator.py` — reproducibility for a fixed seed, correct shape/
  columns, green sites cooler than reference during daylight, cooling
  effect correlating with solar radiation (not a fixed offset), UTCI
  category/value consistency, injected anomalies being detectable,
  down-station and active-row field completeness.
- `quality_checks.py` — completeness calculation, time-gap detection,
  implausible-reading detection, stuck-sensor run detection, station status
  shares summing to 100%.
- `statistics_utils.py` — pair comparison deltas, cooler-hours counting,
  hottest-period ordering, hourly profile averaging, summary statistics,
  station metadata lookups.

## Extending to real field stations

The UI never talks to SQLite directly. Every page reads through
[`src/cached_data.py`](src/cached_data.py) → [`src/data_service.py`](src/data_service.py),
which defines an abstract `DataSource` with `get_stations()`,
`get_readings()`, and `get_latest_readings()`. To connect a real monitoring
network later:

1. Implement `APIDataSource` in `src/data_service.py` (the class and method
   stubs already exist — they currently raise `NotImplementedError`).
2. Set `DATA_SOURCE_MODE = "api"` in `config/settings.py`.
3. Nothing in `app.py` or `views/*.py` needs to change.
